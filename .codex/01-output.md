# Output discipline (what you write back)

- Prefer diffs that are easy to review.
- Keep explanations minimal: intent, risk, tests.
- Never claim "fixed" or "secure" without a test or a proof.
- When behavior changes, show:
  - old behavior
  - new behavior
  - test that locks it in

Review notes:
- When you identify a point in a review, file it under the correct thematic rubric in `snapshot/REVUE - INNLOG - 27-12-2025.md`.
